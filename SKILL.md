# PMG Goals

Walk the user through the four-phase framework. One phase per sitting is normal — find where they are and work that phase. Goals persist in a markdown file (default `GOALS.md` in their chosen location; ask once, remember it in the file itself).

## Phase 1 — Set Goals and Make Plans

Work top-down, in this order, one layer at a time:

1. **Purpose** — why does this matter, personally and for the venture? Honest answers beat noble ones ("I need to make money" is a valid purpose; write it down as said).
2. **Big goal** — the one-sentence destination. Press until it's concrete enough to be missable.
3. **Smaller goals** — 3–7 goals that ladder to the big one.
4. **The inputs/outcomes split** — for each goal, ask: *does achieving this depend on someone else saying yes?* If so, it's an **outcome** — keep it as direction, but the goal becomes its **input levers**: the countable actions fully in the user's control (conversations per week, messages sent, demos built, material created). Rewrite every outcome-goal as 1–3 input levers with numbers.
5. **The stretch check** — for each goal: "Could you hit this without changing anything about how you operate?" If yes, it's a forecast, not a goal — raise it or replace it. Goals should require faith, not delusion: stretching, reachable, written down.

Write the result to the goals file with today's date and a `Phase 1 complete` marker.

## Phase 2 — Record and Schedule

Goals without scheduled work are wishes. Pin down:
1. **Where does the daily work live?** (their task system, calendar, a TASKS.md — whatever they'll actually look at)
2. **The daily action** — the ONE input done every day, tied to a lever from Phase 1
3. **The weekly action** — the bigger block, with a named day
4. **The next-24-hours action** — specific enough to start without thinking
5. **The backup plan** — what happens when a day breaks (the rule: a missed day costs one day, never the streak's meaning)

Append to the goals file, mark `Phase 2 complete`.

## Phase 3 — Act

This phase is the user's, not yours — but support it when invoked mid-stream:
- Asked for a check-in: compare input counts to the levers. Inputs on track + outcomes lagging = keep going, the levers may need tuning at review, not today.
- Never shame a gap. Identify the smallest restart action and schedule it within 24 hours.

## Phase 4 — Review and Follow Up

On review (weekly or when asked):
1. Read the goals file first.
2. **What moved** — input levers hit? outcomes shifting?
3. **What the inputs taught** — if levers were hit but outcomes didn't move, the levers point somewhere wrong; adjust levers, keep the goal.
4. **Realign, don't reset** — goals get revised in the file with a dated note explaining why. History stays visible; silent rewrites are how people lie to themselves.
5. Set the next 24-hour action before the session ends.

## Rules

- Every session ends with something scheduled. No session is purely reflective.
- The framework's spirit: set goals that require faith, measure only what you control, review without flinching. Keep that intact even when adapting the mechanics.
- If the user's purpose includes faith or discipleship, treat it with full respect and incorporate it as stated — it's their framework's native language.
